⚠ Alerta para mentores

1. Es un repaso para jugar, no una clase nueva. Ningún tema se explica desde cero. Cada estación empieza con una dinámica donde los estudiantes predicen, descubren o corrigen, y el mentor solo completa lo que falte. Si sientes que estás hablando más de tres minutos seguidos, lanza una pregunta.

2. No depende de instalaciones. La parte de MongoDB y Mongoose se trabaja leyendo y escribiendo código en un editor de texto (VS Code o Bloc de notas), sin ejecutarlo. La parte de React se trabaja en StackBlitz (vite.new/react), como en la S20. Atlas en el navegador es opcional, para quien recuerde su usuario.

3. Antes de que lleguen los estudiantes (10 min). Prueba desde un computador de la sala que abran vite.new/react y cloud.mongodb.com, y deja proyectada la agenda. Ten listos en el canal del grupo los códigos del Anexo B para compartirlos en la Estación 3.

4. Puestos fijos: el trabajo en pareja es con el vecino. Las sillas no se mueven. Cuando la guía dice "en parejas", es con la persona del puesto de al lado. Si alguien queda solo, se une a la pareja más cercana como trío.

5. Todo gira alrededor del emprendimiento de cada estudiante. El mentor usa la repostería "Dulce Horno" como ejemplo. Los estudiantes trabajan con su emprendimiento (Opción 1) o con un caso del Anexo C (Opción 2), y usan el mismo en las tres estaciones para que vean el hilo completo.

6. Problemas de Git/GitHub o de cuentas olvidadas. Se anotan y se derivan a la mentoría entre sesiones. No se resuelven en clase.

Estación 2 · El control de calidad: Mongoose y Express (30 min)

Recordatorio en una frase (S19): el esquema de Mongoose es la lista de reglas que debe cumplir un dato para entrar a la despensa, y las rutas de Express son los meseros que reciben los pedidos.

El esquema de Dulce Horno (proyectarlo durante toda la estación)

const usuarioSchema = new mongoose.Schema({

  nombre: { type: String, required: true },

  email:  { type: String, required: true },

  edad:   { type: Number, min: 14 },

  rol:    { type: String, enum: ['cliente', 'admin'], default: 'cliente' }

});

Las cinco rutas de la API

app.get('/api/usuarios', ...)        // listar todos

app.get('/api/usuarios/:id', ...)    // buscar uno

app.post('/api/usuarios', ...)       // crear

app.put('/api/usuarios/:id', ...)    // actualizar

app.delete('/api/usuarios/:id', ...) // borrar

Dinámica 1: Adivina el código (12 min)

Explica las señas: un dedo es 201 (creado), dos dedos es 400 (dato con error) y tres dedos es 404 (no existe). El mentor lee cada pedido; a la cuenta de tres, todos muestran su respuesta al mismo tiempo. Antes de revelar, pide a alguien que haya respondido distinto a la mayoría que explique su razonamiento.

Bloque 5 · El viaje de un pedido (20 min)

Esta es la dinámica más importante del día: une los tres temas en una sola historia. Se hace con los estudiantes de pie, en sus puestos.

Preparación (3 min)

El mentor asigna cuatro roles a cuatro estudiantes sentados en fila (cada fila de la sala puede ser un equipo). Cada uno dice su rol en voz alta:

Rol

Qué dice cuando le llega el pedido

1. La página (React)

"El cliente llenó sus datos y hizo clic en Registrarme. Envío un POST a /api/usuarios con..." (lee los datos)

2. El mesero (Express)

"Recibo el POST en la ruta /api/usuarios y se lo paso al control de calidad"

3. El control de calidad (Mongoose)

"Reviso las reglas del esquema..." y responde "cumple" o "no cumple porque..."

4. La despensa (MongoDB)

Si cumple: "Lo guardo en la colección usuarios. Respondo 201". Si no le llega nada: se queda en silencio

Las rondas (12 min)

El mentor entrega un pedido distinto a cada fila (lo dice en voz alta o lo escribe en el tablero). Cada fila lo hace pasar por los cuatro roles frente a la sala:

  1. Pedido correcto: nombre "Valentina", email "vale@correo.com". Llega hasta la despensa y responde 201.
  2. Pedido sin nombre. El control de calidad lo detiene, la despensa no recibe nada y la página le muestra un error 400 al cliente.
  3. Pedido con rol "jefe". Se detiene en el control de calidad por el enum.
  4. Pedido para buscar a un usuario con un id que no existe (GET). El mesero va a la despensa, no encuentra nada y responde 404.

📝 Para guiar

Pregunta para cada ronda: "¿En qué pieza se detuvo el pedido? ¿Qué ve el cliente en la pantalla?"

Cierre de la dinámica (5 min): pregunta "¿Cuál de estas cuatro piezas ya tiene tu proyecto final? ¿Cuál le falta?". Las respuestas son información valiosa para la mentoría de las próximas semanas: anótalas.

⏱ Ritmo / pacing

Si la sala tiene pocas filas o pocos estudiantes, hagan las cuatro rondas con el mismo equipo rotando los roles. Lo importante es que todos digan al menos una vez el texto de un rol.

Código B · src/components/ProductoCard.jsx

import { useState } from 'react';

 

function ProductoCard(props) {

  const [cantidad, setCantidad] = useState(0);

 

  return (

    <article className="tarjeta">

      <h3>{props.nombre}</h3>

      <p>{props.descripcion}</p>

      <p className="precio">{props.precio}</p>

 

      <button onClick={() => setCantidad(cantidad + 1)}>

        Agregar al pedido

      </button>

      <p>En tu pedido: {cantidad}</p>

    </article>

  );

}

 

export default ProductoCard;
